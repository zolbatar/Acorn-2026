# Trellis SWI compatibility test matrix

This matrix links the hosted dispatcher inventory in
[`trellis-swi-inventory.yaml`](trellis-swi-inventory.yaml) to executable
checks. “Partial” means the current hosted implementation or its tests cover a
useful slice, not every historical reason, flag, buffer limit, or error case.

Load accepts bounded caller-path HostFS `&064` BASIC64 source, rejects capabilities/primitive imports, requires active dependencies, and rolls back failed Start. A same-title Load supports one compatible-immediate whole-module replacement class: exact public SWI identities/contracts and exported PROC/FN signatures, unchanged dependencies/capabilities/lifecycle metadata and full state/type schema; it preserves module/entry-cell IDs and workspace, advances all exports together, and old leases retain old-source calls. Incompatibility leaves the old module active; foundation modules cannot be replaced. Candidate Start and old Quiesce/Finalise are not rerun. This transactional hosted behavior is safer but differs from PRM reason 1, which kills the duplicate and all instantiations before initializing the new `&FFA` image. Delete runs Quiesce/Finalise and refuses foundation/dependency removal. Other historical reasons are structured rejections; pointer-bearing reasons 12/18 are not emulated. | `OS_CLI` and configuration | `tests/trellis_classic_module_commands.rs`; `tests/trellis_mos_introspection.rs::wp51_mos_introspection_matches_read_only_queries_and_tracks_live_generations`; `tests/trellis_authorization.rs`; `tests/trellis_mos_configuration.rs::trellis_configure_status_persist_and_enforce_task_scoped_write_authority`; `tests/trellis_configuration_recovery.rs`; `swi::tests::configure_accepts_supported_values_and_conf_abbreviation`; desktop command/configuration tests; `tests/mos_calls.rs` CLI bridge | Partial migration. `TrellisCommands.bas64` owns OS_CLI (`&05`) and exposes read-only `*INSPECT MODULES`, `MODULE`, `SWI`, and `DEFINITION` (`SOURCE` alias); classic routes are `*Modules`, `*RMLoad`, `*RMRun`, `*RMKill`, and conditional `*RMEnsure`. ## Minimum verification commands

The first module slice can be checked independently with:

```sh
cargo test --no-default-features --lib boot::tests
cargo test --no-default-features --lib trellis::tests
cargo test --no-default-features --lib basic_compat::system_profile::tests
cargo test --no-default-features --lib swi::tests::error_task_and_module_foundation_sw_is_are_owned_by_basic64_modules
cargo test --no-default-features --lib swi::tests::swi_errors_and_x_form_errors_use_the_documented_task_scoped_block
cargo test --no-default-features --lib swi::tests::module_manager_loads_inspects_and_unloads_guest_source_modules
cargo test --no-default-features --lib swi::tests::module_manager_rolls_back_failed_guest_start_and_protects_foundation
cargo test --no-default-features --lib swi::tests::module_manager_enforces_guest_capability_and_dependency_boundaries
cargo test --no-default-features --lib swi::tests::basic64_memory_module_owns_task_scoped_dynamic_area_lifecycle
cargo test --no-default-features --lib swi::tests::console_swis_dispatch_through_interpreted_module_definitions
cargo test --no-default-features --lib swi::tests::console_definition_replacement_keeps_the_entry_cell_and_rejects_bad_contracts
cargo test --no-default-features --lib swi::tests::console_string_swi_enforces_the_declared_terminator_bound
cargo test --no-default-features --lib swi::tests::os_read_line_
```

The existing full project suite remains the broad compatibility gate. The
inventory intentionally records missing focused cases instead of treating
successful whole-project tests as proof of complete historical conformance.
