# Tokenized BASIC compatibility matrix

## Purpose

Keep saved-file decoding, token interpretation, and execution coverage separate. The decoder preserves token bytes and normalizes observed record layouts into the same line-oriented program model. The compatibility runner then selects language behavior; a successful load does not imply that the program can run.

The user requirement is to load tokenized programs from every earlier BBC BASIC release. The reference manual identifies BASIC I, II, III, IV, V 1.04, V 1.05, and VI 1.05. Current fixtures establish a useful starting point without claiming complete coverage.

## Release inventory

| Release | Target and distinguishing evidence | Fixture coverage |
| --- | --- | --- |
| BASIC I | Early BBC Micro Model A/B; original interpreter. | No release-identified saved file yet. |
| BASIC II | BBC Model A/B; adds `OPENUP` and `OSCLI`. | No release-identified saved file yet. TDU-01 is retained as an optional graphics-development input and shared-layout evidence; its ROM version is unknown, so it is not BASIC II coverage. |
| BASIC III | BBC Model B+; largely BASIC II plus the US spelling `COLOR`. | No release-identified saved file yet. |
| BASIC IV | BBC Master series and 65C12 second processors. | TETRIZ 1.5 is Master-targeted BASIC IV-class evidence; exact ROM revision is unknown, and its use of BASIC IV-only tokens is not established. It is not a required whole-program execution target. |
| BASIC V 1.04 | ARM / RISC OS. | No independent saved binary yet. |
| BASIC V 1.05 | ARM / RISC OS; later interpreter release. | No independently saved binary yet. ClockSP5's generated token file exercises an ARM token profile but does not verify this interpreter release; `5.08` is the program version. |
| BASIC VI 1.05 | ARM / RISC OS; IEEE 8-byte real representation. | No independent saved binary yet. |

The release distinctions above follow the [BBC BASIC history appendix](https://www.riscos.com/support/developers/bbcbasic/appendices/basichistory.html). It identifies BASIC IV as the Master / 65C12 release and distinguishes V 1.04, V 1.05, and VI 1.05.

## Observed saved-program layouts

The current corpus contains two byte-level line-boundary layouts:

| Layout | Boundary bytes | Evidence |
| --- | --- | --- |
| Shared boundary carriage return | A `0D` at the next-record boundary terminates the prior line and starts the next record. | `tdu-01-test.bbc` from public-domain TDU-01 and `tetriz-master-basic4.bbc` from public-domain BBC-134. |
| Separate line carriage return | A line-ending `0D` is inside the record length, followed by another `0D` marking the next record. | The project-generated ARM BASIC V ClockSP5 and echo fixtures. |

The shared decoder auto-detects these layouts per program, rejects a file that mixes them, preserves each line's token bytes, and scans line references with layout-appropriate token rules. The inferred layout is not an exact interpreter-version identifier.

The matrix deliberately labels exact ROM revisions as unknown where the disk provenance does not identify them. The shared-boundary profile now includes a conservative common graphics statement subset alongside leading-`REM`, literal-string `PRINT`, and `END`; it is not an inferred BASIC I/II/III/IV release. ClockSP5 exercises the ARM token profile, but its binary was generated from text and therefore does not verify a binary saved by a real BASIC V interpreter.

## Development and corpus fixtures outside release acceptance

These authentic programs are useful engineering inputs, but neither is a required whole-program compatibility acceptance target. Their bytes remain in the corpus for decoder and token evidence.

| Program | Evidence and intended use | Whole-program status |
| --- | --- | --- |
| TDU-01 `$.TEST` | Authentic BBC Micro save with unknown ROM version; 4 line records. It remains the active source for developing the common graphics slice, especially `MODE`, VDU control, and the common drawing statements. | Not required to run end-to-end. Procedure flow, direct memory operations, and custom machine-code routines extend beyond the current graphics/language slice. |
| Master TETRIZ 1.5 `T.MTETRIZ` | Authentic Master-targeted save, BASIC IV-class evidence with unknown ROM revision; 362 lines and 2 resolved references. Retain for saved-file decoding and future token/version analysis. | Decode evidence only for now. Execution currently stops at `ON` on line 60, and the game also uses Master-oriented graphics, sound, machine-code, and SRAM/high-score facilities. It is not a required execution or graphics acceptance target. |

The first graphics implementation is an additional common-statement slice, not a new release-specific execution profile. `OS_WriteC` feeds the VDU stream parser, while BASIC `LINE`/`MOVE`/`DRAW`/`PLOT` statements use the hosted `OS_Plot` service. The retained scene records logical coordinates and clipping state; a single-window raster renderer now displays it in a fixed 640 × 256 framebuffer. This does not execute machine-code `CALL` statements or claim full VDU command coverage. TDU-01 guides this work without becoming a release or whole-program compatibility requirement.

[`examples/mandelbrot/mandelbrot.bas`](../examples/mandelbrot/mandelbrot.bas) is copied from the RISC OS 5.22 listing in [“Mandelbrot plotters for BBC BASIC”](https://barrowbiker.wordpress.com/2016/12/25/mandelbrot-plotters-for-bbc-basic/) (Barrowbiker's Blog, December 25, 2016). The post invites readers to use the code but does not state a formal license. This is readable text rather than a tokenized BASIC `SAVE`, and it has not been verified against a specific BASIC V/VI release. It exercises RISC OS extended `MODE` blocks and `ColourTrans` SWIs beyond the current hosted slice, and its full 1680 × 1050, 8192-iteration workload is intended for later renderer/performance evaluation, not current execution acceptance. See the fixture README for details.

## Test harness

Run `cargo test`. The `tokenized_compatibility` integration test walks the checked-in corpus and checks each program's detected layout, line count, line-reference count, and unresolved-reference count. Decoder unit tests also cover malformed records, quoted/DATA/REM text, classic `DELETE` line references, ClockSP5's exact reference destinations, and the authentic BBC Micro and Master fixtures' line boundaries. The shared-boundary core fixture can be run with `BASICLOAD examples/tokenized-compat/classic-core-smoke.bbc` followed by `BASICRUN`.

When adding a fixture, record its source, claimed interpreter/version, license or redistribution terms, layout, line/reference counts, and whether its bytes came from an actual BASIC `SAVE` or a project converter. Do not promote an unpinned fixture to a specific release row based only on its syntax.
