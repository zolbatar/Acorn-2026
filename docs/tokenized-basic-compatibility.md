# Tokenized BASIC compatibility matrix

## Purpose

Keep saved-file decoding, token interpretation, and execution coverage separate. The decoder preserves token bytes and normalizes observed record layouts into the same line-oriented program model. The compatibility runner then selects language behavior; a successful load does not imply that the program can run.

The user requirement is to load tokenized programs from earlier BBC BASIC versions. The exact release list and version-selection mechanism remain open. Current fixtures establish a useful starting point without claiming complete BASIC I/II/III/IV/V/VI coverage.

## Observed saved-program layouts

The current corpus contains two byte-level line-boundary layouts:

| Layout | Boundary bytes | Evidence |
| --- | --- | --- |
| Shared boundary carriage return | A `0D` at the next-record boundary terminates the prior line and starts the next record. | `tdu-01-test.bbc`, extracted from the public-domain TDU-01 BBC Micro disk. |
| Separate line carriage return | A line-ending `0D` is inside the record length, followed by another `0D` marking the next record. | The project-generated ARM BASIC V ClockSP5 and echo fixtures. |

The shared decoder auto-detects these layouts per program, rejects a file that mixes them, preserves each line's token bytes, and scans line references with layout-appropriate token rules. The inferred layout is not an exact interpreter-version identifier.

The matrix deliberately labels the TDU-01 sample's ROM version as unknown. Its record layout is evidence of a real older BBC Micro file, not proof that a specific BASIC ROM release has been covered. ClockSP5 exercises the ARM token profile, but its binary was generated from text and therefore does not verify a binary saved by a real BASIC V interpreter.

## Test harness

Run `cargo test`. The `tokenized_compatibility` integration test walks the checked-in corpus and checks each program's detected layout, line count, line-reference count, and unresolved-reference count. Decoder unit tests also cover malformed records, quoted/DATA/REM text, classic `DELETE` line references, ClockSP5's exact reference destinations, and the authentic BBC Micro fixture's line boundaries.

When adding a fixture, record its source, claimed interpreter/version, license or redistribution terms, layout, line/reference counts, and whether its bytes came from an actual BASIC `SAVE` or a project converter. Do not promote an unpinned fixture to a specific release row based only on its syntax.
